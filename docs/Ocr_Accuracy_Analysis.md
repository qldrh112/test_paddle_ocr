# OCR 정확도 비교 분석 가이드

이 문서는 프로젝트에서 사용 중인 정확도 측정 방식(`scripts/compare_results.py`)과 주요 지표에 대한 상세 설명을 담고 있습니다.

## 1. 측정 방식: Bag-of-Cells 비교
표의 행/열 구조가 완벽하지 않더라도 실제 데이터가 얼마나 잘 추출되었는지를 측정하기 위해 아래 방식을 사용합니다.

1.  **데이터 수집**: 정답 레이블(GT)과 OCR 결과물에서 모든 셀의 텍스트를 추출합니다.
2.  **유사도 매칭**: 각 셀의 텍스트를 `SequenceMatcher`를 사용하여 비교합니다.
3.  **임계값(Threshold)**: 유사도가 0.8(80%) 이상이면 매칭된 것으로 간주합니다.

## 2. 주요 성능 지표 (Metrics)

| 지표 | 의미 | 계산 방식 |
|------|------|-----------|
| **Precision** | OCR이 추출한 데이터 중 정답인 비율 | 매칭된 셀 수 / 예측된 전체 셀 수 |
| **Recall** | 정답 데이터 중 OCR이 성공적으로 찾아낸 비율 | 매칭된 셀 수 / 정답 데이터 전체 셀 수 |
| **F1-Score** | Precision과 Recall의 조화 평균 | 2 * (Prec * Recall) / (Prec + Recall) |
| **Exact Match** | 100% 일치하는 셀의 개수 | 텍스트가 토씨 하나 안 틀리고 일치하는 수 |

## 3. 프레임워크별 주요 오류 패턴 분석

### 🔴 PaddleOCR
- **구조 인식 패배**: 표의 테두리 선이 흐리거나 복잡한 경우 표 자체를 감지하지 못함.
- **오류 증상**: CSV 파일이 생성되더라도 데이터가 없거나(0 rows) 엉뚱한 텍스트만 포함됨.

### 🟡 Tesseract
- **노이즈 취약**: 배경에 있는 글자나 낙서, 도장을 표의 셀 데이터로 오인하여 Precision이 낮아짐.
- **오류 증상**: 한 행에 있어야 할 데이터가 여러 행으로 쪼개지거나 'nan' 값이 대량 발생함.

### 🟢 EasyOCR
- **비교적 안정적**: 텍스트 인식률이 가장 높지만, 행 사이의 간격이 좁으면 서로 다른 행을 하나로 합치는 경우가 발생함.

## 4. 정확도 향상을 위한 권장 설정

1.  **이미지 해상도**: 300 DPI 이상의 스캔본 권장.
2.  **전처리 (Cropping)**: `preprocess_crops.py`를 사용하여 불필요한 영역을 제거하면 F1-Score가 평균 30~50% 향상됩니다.
3.  **임계값 조정**: 특정 도메인(예: 계좌번호)은 `compare_results.py`에서 매칭 임계값을 0.9 이상으로 높여 엄격하게 관리하는 것이 좋습니다.
