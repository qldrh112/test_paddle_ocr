## 금융거래조회서 데이터 추출 자동화(Audit-OCR)' 프로젝트 문제 정의
1. 데이터 신뢰성 및 무결성 결여 (Reliability Gap)
회계 감사의 핵심은 '숫자'의 정확성입니다. 현재의 수동 프로세스는 치명적인 리스크를 내포하고 있습니다.

휴먼 에러 발생: 대량의 조회서를 사람이 직접 눈으로 보고 엑셀에 타이핑하는 과정에서 오타나 금액 누락이 빈번하게 발생합니다.

검증 체계의 부재: 사람이 추출한 데이터가 스캔본 PDF와 일치하는지 교차 검증할 자동화된 수단이 없어, 데이터의 무결성을 보장하기 어렵습니다.

2. 비정형 서식의 파편화 (Template Complexity)
금융기관마다 조회서 양식이 다르며, 동일 은행이라도 시점마다 서식이 변경됩니다.

좌표 기반 추출의 한계: 기존 OCR 방식처럼 특정 위치(X, Y 좌표)의 값을 읽는 방식은 서식이 조금만 틀어져도 오작동합니다.

다양한 데이터 레이어: 스캔된 이미지 PDF(A1)와 텍스트가 살아있는 디지털 PDF(A2)가 혼재되어 있어, 단일 로직으로는 대응이 불가능합니다.

3. 엄격한 보안 및 규제 준수 (Security Constraints)
금융 데이터는 최고 수준의 보안이 요구되므로 일반적인 클라우드 솔루션을 사용할 수 없습니다.

외부 유출 금지: Google Vision이나 AWS Textract 같은 외부 클라우드 OCR API 사용이 엄격히 금지되어 있습니다.

로컬 환경의 기술적 제약: 오직 온프레미스(Local) 환경에서 구동되는 엔진만으로 높은 정확도를 구현해야 하는 기술적 난관이 존재합니다.

4. 낮은 업무 효율성과 계절적 업무 부하 (Operational Inefficiency)
감사 시즌(1~3월)에 집중되는 업무량은 인적 자원의 고갈을 초래합니다.

단순 반복 작업의 과부하 (UserStory-001): 숙련된 회계 인력이 단순 데이터 타이핑에 시간을 허비함으로써, 고부가가치 판단 업무에 집중하지 못하는 기회비용이 발생합니다.
