# OCR 프레임워크 성능 비교 요약 (PaddleOCR vs EasyOCR vs Tesseract)

## 1. 개요
본 문서는 `paddleocr` (v2.6 추정), `easyocr` (v1.7), `tesseract` (v5.5) 3가지 OCR 프레임워크의 성능을 비교 분석한 결과입니다.
분석은 동일한 테스트 이미지 11장에 대해 수행되었습니다.

## 2. 주요 결과 요약

| 프레임워크 | 평균 처리 시간 (초/이미지) | 평균 검출 영역 수 | 비고 |
| :--- | :--- | :--- | :--- |
| **Tesseract** | **1.60초** (가장 빠름) | 363개 | 글자 단위 분리가 많아 영역 수가 많음 |
| **EasyOCR** | 10.98초 | 92개 | 적절한 단어/문장 단위 검출 |
| **PaddleOCR** | 67.58초 (매우 느림) | **0개** | **(실패) 검출된 텍스트 없음** |

### 특이사항
- **PaddleOCR 실패**: 현재 설정된 환경에서 PaddleOCR 테스트가 정상적으로 동작하지 않았습니다. 이미지를 처리하는 데 매우 긴 시간이 소요되었으나(평균 67초), 결과적으로 아무런 텍스트도 검출하지 못했습니다(`total_regions: 0`).
    - 원인 추정: 모델 로드 실패, CPU 연산 과부하, 또는 이미지 전처리 문제 등.
- **Tesseract 성능**: 가장 빠른 처리 속도를 보여주며, 검출된 영역의 신뢰도(Confidence)도 평균 0.88로 양호합니다.
- **EasyOCR 성능**: Tesseract보다 느리지만, 초기화 비용(약 10~15초)을 제외하면 준수한 속도를 보입니다.

## 4. 결론 및 제안
1. **PaddleOCR 점검 필요**: PaddleOCR의 성능을 제대로 평가하기 위해, 실행 환경 및 코드를 디버깅하여 정상적으로 텍스트가 검출되도록 수정해야 합니다.
2. **비교 스크립트**: `compare_all_frameworks.py` 스크립트를 사용하여 추후 PaddleOCR 수정 후 다시 비교를 수행할 수 있습니다.
